# 账号模式与本地数据迁移

本文件定义本地/账号数据的导入、迁移、备份和恢复。故事与卡牌扩展仍是待实施契约；服务器启动与操作见 [服务端说明](../../server/README.md)。

## 模式边界

- 本地模式继续使用 IndexedDB schema/data format v4，离线学习、会话、练习和本地正式复习保持可用。
- 账号模式以 Java 服务正式状态为唯一云端来源；账号模式正式复习第一版要求在线提交。
- 两种模式不自动双向同步。账号缓存、草稿和待确认提交按“服务器地址 + 用户 ID”隔离。
- 切换账号必须卸载旧模式、停止提醒、取消旧请求并清理账号私有页面缓存；本地模式数据库不删除。

## 首次登录迁移

1. 展示本地词库、词条、学习目标、笔记、练习、会话、复习状态和日志数量。
2. 显示目标服务器地址和账号用户名，要求用户主动勾选“上传到该账号”。
3. 上传前提供当前本地完整备份；用户不下载备份也可以取消迁移。
4. 生成本地稳定的 `migrationBatchId`，预览与确认使用同一快照指纹。
5. 服务端验证数据格式、ID、引用、调度版本、34 权重和日志链。
6. 服务端以 `(userId, migrationBatchId)` 建立唯一回执；同批次同内容返回第一次结果，同批次不同内容冲突。
7. 默认将上传内容作为独立导入集合追加；已有云端数据不被覆盖，不按词面自动合并掌握度。
8. 成功不删除本地数据；失败保留本地数据和待上传快照。

## ID 与日志映射

- 客户端提交原 ID 与稳定批次 ID，服务端在用户范围内保留无损字符串映射。
- 词条、学习目标、词库成员、笔记、会话、练习、复习状态和日志的引用必须在同一请求中保持一致。
- 卡片身份与学习目标映射一致；日志按 `reviewedAt`、`submissionId` 去重并保持 before/after 链。
- 已有云端状态与导入状态不合并。导入学习目标使用独立调度状态；若用户以后明确选择合并，另建设计和迁移。
- 导入历史标记 `source=migration`、`rewardEligible=false`；日志和旧会话不能重复产生经验、等级或成就。

## 版本与失败

- 迁移请求带 `sourceSchemaVersion`、`sourceDataFormatVersion`、`schedulerPackageVersion`、`schedulerModelVersion` 和配置哈希。
- 不兼容模型、损坏日志链、缺失引用和未来格式在写入前失败。
- 服务端在单事务中写导入集合、业务表、迁移回执和审计元数据；任一失败全部回滚。
- 重试使用原批次 ID；成功响应丢失后重试返回原回执和计数。
- P2 以用户范围内的 `fm_import_id_map` 保存原始 ID 到目标 ID 的映射；导入日志和奖励事件标记为不可奖励。

## 用户级备份

- 现有 IndexedDB“全库覆盖”只属于本地模式。
- 账号备份导出只查询当前认证用户的数据；管理员接口不能通过普通备份 API 绕过归属。
- 恢复先预览用户范围、版本和引用，再在单事务内替换当前用户业务数据；不删除账号、偏好、令牌或其他用户数据。
- 恢复失败保持当前账号数据不变。生产数据库备份与用户级 JSON 备份分开实现、验证和授权。
- P2 账号备份还保存正式复习回执、奖励事件、迁移回执和 ID 映射；恢复不触碰其他用户。


## H 阶段新增迁移边界

- 现有 v3/v4 词库、FSRS 与回执迁移继续有效；新卡片策略、冒险安装、存档和素材需要各自显式格式版本，实施时同步本地、Java、CLI 与备份校验器。
- 旧评估记录缺失 `assessmentPolicyVersion` 时解释为 legacy-v1，不套用新翻面规则重算旧日志；词条、学习目标和 FSRS 卡片 ID 保持原身份。
- 新导入 `.fmbook` 是内容安装，不是用户存档恢复：它不能携带并覆盖个人凭据、笔记、复习卡片、关系值或奖励。
- 普通 TSV 仍能只导入词库；绑定固定冒险模板要显式选择，不自动上传或生成冒险历史。
- 内容包的资源与数据库通过 staging/manifest 切换确保原子可见；坏包、资源缺失、冲突或取消不破坏已装版本。
- 进行中的冒险固定安装版本，升级须提供节点/词条映射。无法安全映射时保留旧 run，允许新建；不能无声重置 FSRS 或跳过未完成剧情。
- 帐号和本地备份新增故事、遭遇检查点、伙伴偏好、关系/奖励回执及不可变资源引用；私有资源须随归档或明确旁包导出，不能仅提供一个已失效的 URL。
- 用户恢复检查资源、状态引用和日志链，再切换可见数据；失败保持当前存档。本地与账号资料继续隔离，切号不共享故事草稿和迟到响应。
- 无旧故事的账号迁移后默认未开始冒险，不能用既有学习日志反向刷满关系和剧情；现有词汇熟悉度可用于选择教学队列，不等于重新发奖。
- 验收覆盖：v4→新版本、旧备份恢复、新故事归档往返、缺资源回滚、跨用户拒绝、包升级中断、同批次重试与恢复后奖励不重复。


## 卡牌版追加边界

新战斗需备份牌组、卡实例、已确定的牌序/游标、回合阶段、敌我状态、待确认动作、奖励回执和 battleRulesVersion；恢复到最新已提交回合，不回放历史动作重新抽牌或发奖。身份、时区、素材版本和学习规则的兼容要求继续有效。

历史歌词/弹幕/卡片雨 modeId 保留为只读兼容值，已有未完会话可显式转换到经典学习或归档；清除导航/组件不删除 FSRS 和旧日志。已有角色资产换新版时，角色 ID、用户偏好和故事引用保持不变，资源版本显式升级。

角色服装扩展以稳定 characterId 与 costumeId 引用，不重建伙伴身份、学习目标或关系记录；海滩/旅行装素材版本纳入内容清单及完整备份。

## 词条文件与旧数据来源

### 新版 TSV

- 默认分隔符是字面制表符 `\t`，使用 Papa Parse 处理引用、空字段和换行。
- 第一列是词面，第二列是主释义，其余列是提示；导入前预览有效行、空行、重复项和错误行。
- 导入采用“解析预览 -> 用户确认 -> 单事务提交”，取消和解析失败都不改变数据库。
- 存在无效记录时禁止确认，避免一次坏文件产生部分导入。
- 当前重复项按目标词库内“规范化英文拼写 + 主释义”精确识别，不静默覆盖。用户逐条选择跳过或作为独立学习目标后再提交；跨词库合并不在 M1-04 实现。
- 同一拼写但不同主释义仍建立独立学习目标，不据此确认 A4 的长期共享规则。
- 导入词条、学习目标、词库成员关系和批次回执在同一个 Dexie 事务中写入；任一行失败时全部回滚。

### 旧 CLI 数据

旧 CLI 的实际行为是：配置写 `separator: '\t'`，运行时却改成四个空格；卡片缓存是逐行 JSON，会话历史是 `cache/<词库>/<词库>_<组号>.json` 加 `history.log` 的行号/模式信息。兼容策略：

- 新导入器默认不复制这个替换行为，标准 TSV 的制表符保持原义。
- 若用户选择“旧 CLI 四空格格式”，使用独立适配器并显示预览，不能自动猜测和混合分隔符。
- 旧 JSON 卡片映射 `word`、`describe`、`clue[]`；旧历史只提供恢复提示，不直接视为正式复习日志。
- 两个仓库当前都没有可读取的真实词表、缓存、历史或本地数据库文件；在没有样本前不宣称已完成旧数据迁移。

### 旧 Web 数据

- `fm.sql` 只是 2021 年演示种子，包含 21 个演示用户、23 个单词和明文演示密码；Mongo 内容与 Redis 会话没有仓库内快照。
- 新版不直接读取旧运行中的数据，也不复制明文密码、用户账号或会话表。
- 若以后找到个人 MySQL/Mongo 导出，先新增只读、固定输入的迁移适配器和脱敏夹具，再迁移词库、词条、释义、提示和笔记；旧浏览进度不作为 FSRS 历史。

### 本地备份

- 导出在一个只读 Dexie 事务中读取所有表，生成带 `snapshotVersion`、`schemaVersion`、`dataFormatVersion` 和 UTC 导出时间的 JSON 文件。
- 文件名使用 UTC 时间，内容使用两空格格式化 JSON 并以换行结尾；文件不加密，界面明确提示其包含私人学习数据。
- 备份下载本身不修改数据库；导出的表计数用于确认真实读取范围，不能替代后续恢复验收。
- 恢复先执行 Zod 结构校验和跨表引用校验，再显示版本、导出时间和表计数；用户明确确认覆盖后才开始写事务。
- 恢复在一个 Dexie 读写事务中清空并重新写入全部表；任意写入失败会回滚到恢复前数据。非法 JSON、未来版本和损坏引用在写入前失败。
- 当前导出 schema/data format v4；导入兼容 v3 快照，在写入前补齐缺失的队列来源并升级 appMeta 的数据格式标志，再执行跨表引用校验。

## 本地数据与安全

- 本地模式不启用账号密码服务；账号模式使用独立 HttpOnly 会话。两种模式的浏览器数据仍可能被同源脚本、浏览器扩展或共享设备读取。
- 不引入第三方分析脚本、远程字体或默认网络请求。音频等联网能力以后单独评估。
- 导出备份默认是未加密文件，UI 必须说明其包含个人词库和笔记。
- 请求浏览器持久存储只能降低被自动清理的概率，不能承诺永不丢失；定期备份是恢复手段。
- 数据视图显示 `StorageManager.estimate()` 的用量和配额，并提供明确触发 `persist()` 的入口；是否授予由浏览器决定。
- 应用内提醒记录保存在 `appMeta['practice.inAppReminder']`：设置包含随机间隔、每日上限、免打扰与稍后分钟数，状态包含学习日、当日次数、下次时间、稍后时间和当日关闭标记。
- 提醒使用单个 `setTimeout` 和纯策略函数；应用隐藏或关闭时没有后台进程，重新打开后按持久化状态恢复。安静时段结束后重新计算，不使用系统通知。
- 所有用户文本按纯文本渲染；禁止 `v-html` 注入词条或笔记。


## 续作 角色与管理数据

- 个人备份包含内容 lockfile、CompletionReceipt、角色注册引用/解锁来源、BondEvent、run 内牌组和账号级奖励回执。普通分享内容包不携带这些个人事实。
- 新版包只追加独立安装版本，run 迁移时校验角色/节点/卡牌/词条映射；已有结局回执不可被新版覆盖或撤销。跨书继承固定选中的正常结局回执，不引用一个可变的“最新世界 flags”。
- 恢复/整体重置后生成新的 dataEpoch。原数据版本号不能简单倒退并允许旧请求再次生效；旧会话、待提交动作与缓存失效，恢复前已经成功的学习不被当作新请求重放。学习历史时间和调度参数不因此更改。
- 恢复不是把备份中的 owner、角色或管理员权限导入数据库；来源用户 ID 只作映射。ADMIN 角色、默认管理员凭据、服务端权限与审计不属于普通用户恢复数据。
- 沙盒备份显式标 scope=test，只能恢复到 GM 的沙盒；不能用测试通关/解锁作为正常续作前置、奖励或 FSRS 历史。
- 回收归档内容前检查正在进行和已完成 run、角色解锁、结局回执、其他安装版本及可恢复备份的引用；不得因为当前页面没显示就删除公用资源。

恢复旧备份是显式确认的回滚：恢复点后的剧情展示、牌组和关系投影可能撤销，预览须说明范围；不把旧、新存档的数值相加。恢复不会自动重放日志或发放奖励，回滚后的正常行动仍在新 epoch 和恢复后的账本中幂等执行。管理审计、管理员角色与安全凭据不随普通用户回滚。
