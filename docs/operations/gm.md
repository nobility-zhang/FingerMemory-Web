# GM 管理与测试

本文件定义 GM 页面、默认管理员和隔离测试能力。H0-04 已实现
ADMIN/USER 角色、账号类型、首次改密门禁、开发默认管理员一次性初始化、`/gm`
账号目录与脱敏审计。内容校验发布和测试沙盒仍为待实施能力，不能由当前页面或
API 假装成功。页面路径为 `/gm`，支持刷新/直接访问；静态壳可加载，但所有管理
数据与命令都由 API 校验当前角色。HTTP 契约入口见
[OpenAPI](../api/openapi.yaml)。

## 页面与职责

| 页面 | 首版能力 | 不承担的职责 |
| --- | --- | --- |
| 概览 | 当前部署模式、内容版本、worker/数据库可用性、本人沙盒入口 | 不输出环境变量、密码或完整异常堆栈 |
| 账号 | 创建普通/测试账号、授予/撤销 ADMIN、启停账号、查看状态 | 不默认查看正常用户私人答案、笔记、备份；密码重置先复用可信运维命令 |
| 内容与伙伴 | 读取管理内容目录、校验/预览草稿、查看角色表情/服装/对白、发布或归档确定版本 | 不在首版做图形化剧情编辑器，也不允许执行包内脚本 |
| 测试工作台 | 从固定夹具或所选内容创建 sandbox，跳节点、解锁角色、发牌、模拟时钟、重置测试存档 | 不直接改正常用户学习、冒险或奖励 |
| 操作审计 | 按操作者/目标/时间查看结果、失败原因与请求 ID | 不记录明文凭据、完整私人文本或上传原包 |

界面显示醒目的“GM”和“测试沙盒”标识，正常游戏入口与 GM 入口分开。普通用户看不到菜单并且直连 API 仍被拒绝。资料/命令未实现时不提供假成功按钮。

## 默认管理员初始化

默认开发用户名为 `admin`、显示名为“管理员”。数据库迁移、源码、示例文档和公开配置都不包含固定密码。开发入口使用忽略的 `.local/secrets/admin.env`，下列行为是当前实现与后续保持的不变量。

1. 本地开发提供幂等的初始化/启动入口。首次使用在 `/.local/secrets/admin.env` 生成足够强的随机密码并设置文件权限为仅当前用户可读写；也可读取开发者显式提供的密码。文件包含用户名/密码和 bootstrap 开关，只输出凭据文件路径，不把密码写入日志；该目录同时排除出 Git、Docker 构建上下文和分发包，不能认为 .gitignore 会自动保护 Docker。
2. 开发入口复用现有文件，不在每次启动时生成新密码。文件丢失但数据库已有 admin 时进入“使用已有凭据或显式重置”的说明，不伪造一个已经失效的新密码。
3. Spring Boot 在迁移完成、应用对外就绪之前，仅在 bootstrap 启用、尚无管理员且没有成功初始化回执时事务性创建 ADMIN。已有管理员时明确报告复用现有账号；已初始化后即使角色后来改变，也不能靠重启再次提权。username 唯一与初始化回执防止并发创建；后续重启不重置密码、角色或测试数据。
4. 现有同名普通账号不能仅因名字叫 admin 被提升。撞名时失败并给出运维处理方式，由操作人明确改名或执行受控提升；普通注册始终 USER；测试账号也保持 USER，管理员通过自己的 GM 身份管理其隔离沙盒。
5. 本地 dev 入口默认启用此一次性流程；普通集成测试用独立 fixture；生产默认关闭，需运维者显式提供凭据/秘密并启用一次初始化。不能把开发随机文件或固定口令复制进生产镜像。
6. 初始账号设置 mustChangePassword，首次登录先走已有改密能力，完成后进入 GM；服务端在此之前仅允许读取自身改密状态、改密和退出。提供“用户名 admin、密码文件位置、进入 /gm”的简明说明，使测试者能实际登录。
7. 若要恢复管理员访问，复用/扩展现有本地运维命令，不提供匿名 HTTP bootstrap/reset 接口。生产操作不由本规划自动授权执行。

Flyway V4 为用户表追加可信角色、账号类型和首次改密字段；存量用户默认为
USER。已有 `UserAdminCommand` 创建普通用户的行为不能被误记为默认管理员初始化。

## 授权与敏感操作

GM 只接受 ADMIN 的 Cookie 会话，保留 CSRF；PAT 尚未实现，普通用户或仅带
Bearer 前缀不能获得权限或跳过保护。每次请求核验账号有效状态、当前角色与
首次改密状态，降权、停用、改密立即影响后续请求；权限不完全依赖旧 Session
缓存。

授予角色与停用账号须附 reason、expectedVersion、幂等键，成功写入审计；并发操作不能停用或降权最后一个可用管理员。普通注册请求携带 role、isAdmin 或 accountKind 权限字段要拒绝，不能批量绑定到实体。

普通词库/学习/备份接口继续按认证 owner 授权；ADMIN 不等于所有学习接口都可以任意指定 owner。共享内容库由 GM 显式发布，用户私有包不因管理员查看内容列表就变为公开。

密码重置首版使用服务器可信运维命令，重置后撤销相关登录会话/令牌并标记必须改密；GM 页面说明入口，不在未实现一次性秘密回执前提供网页“重置成功”。审计写数据库，包含 actor、action、target、scope、时间、请求 ID、理由和结果摘要；它不是 Git 开发日志，也不保存密码。

## 测试沙盒

sandbox 属于创建它的管理员，可关联明确标记的测试账号和内容版本；默认使用合成夹具，不复制正常用户的私有学习快照。每个 sandbox 有独立 scopeId、dataEpoch、虚拟 Clock、随机源、学习状态、角色名单、故事/战斗状态和奖励账本。存储使用独立的 sandbox 记录/表，不在正常 fm_user_data 上加一个可由客户端改写的 isTest 布尔值。管理员身份/操作审计、正常账号数据和 sandbox 数据分别持久化，并通过新的 Flyway 迁移建立。

| 命令 | 输入/限制 | 预期结果 |
| --- | --- | --- |
| jump-node | 当前锁定内容中有效 nodeId；不允许执行包外路径 | 只改变沙盒节点，并显式重置不兼容的当前遭遇 |
| grant-cards | 已安装定义中的 cardDefinitionId 列表，遵守牌组容量/同名上限 | 沙盒牌组变化，不影响正常收藏与奖励 |
| unlock-character | 可解析的 characterKey 和资源版本 | 沙盒名单解锁，正常账号不变 |
| set-clock | 明确 UTC 时间，可恢复真实时钟 | 只影响本沙盒队列/预览，不改系统时间或其他用户时钟 |
| reset-sandbox | 管理员确认，当前 sandboxVersion | 回到创建夹具，递增 epoch，旧待确认动作不能复活 |

命令带 expectedVersion、reason、稳定 actionId/Idempotency-Key；同 epoch 同 ID 同请求幂等，旧版本冲突可解释。同一命令不可从普通学习 API 伪造 scope；scope 由认证和服务端路由决定。测试数据页面展示 TEST，导出也标 TEST；普通账号恢复/续作解锁拒绝将测试记录当作真实记录。

测试时允许强制失败、为空队列、模拟缺资源等受控场景，先使用确定性夹具/配置，不做任意 SQL/脚本控制台。破坏性调试只能作用于 sandbox。清空与退出不删除共享数据库/容器或正常用户存档。

## 内容制作与发布

GM 内容页复用与用户导入相同的结构/语义/资源校验器。草稿验证通过后在自己的 sandbox 预览，再显式发布共享版本。发布校验需要 manifest、能力、故事入口/结局、角色解锁/服装、词条、声音和许可均完整，不能因操作者是管理员绕过坏包检查。

发布版本不可变；修复创建新版本。归档停止新安装/开局，已固定旧版本的正常 run 继续可恢复。角色定义、对白和装束在对应内容版本中审阅，预览不会解锁正常账号角色。完整规则见 [内容包设计](../architecture/content-pack.md)。

## 必须验收的路径

- 空开发数据库首次启动后能用本地凭据登录 admin、改密并进入 /gm；重启不更改口令和数据；用户名冲突及同时初始化正确处理。
- 普通用户/匿名/普通 PAT 的 GM 请求失败；Cookie 请求加伪 Bearer 前缀仍无法绕过 CSRF；降权后旧会话不能继续 GM 操作。
- 两个并发降权/停用操作不能使最后一个管理员消失。
- 沙盒跳关、发牌、解锁、时间模拟和重置可验证；正常用户的 FSRS、故事、友情、配额与续作前置回执均未变化。
- 坏内容在 GM 与普通导入均被拒绝；只预览不发布，公开目录不可见；发布后新用户可安装，归档不破坏已有 run。
- 每个写操作有权限、幂等/版本、结果与审计；日志和 Git 中不存在初始化密码。
