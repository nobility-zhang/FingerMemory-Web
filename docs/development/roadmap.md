# FingerMemory 实施路线

更新：2026-11-16。本文件仅保存长期路线、依赖与验收标准，不保存逐轮过程、截图、机器状态、完整测试输出或会话交接。实际执行状态和当前阻塞放在 Git 忽略的 `.local/handoffs/current.md`；代码变更历史以 Git 提交为准。

## 方向与基线

已有 Java/MySQL 多用户、固定 FSRS worker、Web 旅店、伙伴切换与基础在线拼写流程可复用。当前“经典卡片”只是旧学习入口，不能当作标准翻面评分已完成。新角色、Phaser、卡牌战斗、音效和完整词库故事包为本路线目标。

H 阶段取代未完成的旧 G 路线；保留原 G2 的学习规则 v2 与 G3 的内容包意图，重设美术、引擎、战斗和仓库卫生要求。新会话不需要恢复已删除的旧聊天，从项目文档、Git 和代码重新确定实际完成范围。

## 开发前约定

提交、代码可维护性与文档职责见 [开发规范](README.md)；素材和 Git LFS 见 [资源管理](assets.md)。执行者先读取根 AGENTS.md、文档导航和忽略目录中的当前交接，再按实际代码确定任务进度。Git 历史记录已经完成的变更，本文件只定义路线和验收。

## 验收规则

测试按真实影响范围选择，不能用截图替代行为，也不能因不提交截图就停止真实浏览器验收。游戏规则验证共享确定性 fixture；数据库事务和两用户隔离使用真实测试数据库；音效必须试听；屏幕与终端至少覆盖当前声明支持的环境。

当前验证结果、失败原因、运行资源归属、commit SHA 和下次操作仅记到忽略的本地交接，并在会话交付中报告。docs 保留“应当如何工作和如何验收”，不积累“某一轮何时执行了哪些命令”。


## 必须串起来的场景

| 场景 | 要验证的结果 |
| --- | --- |
| 只有一个词、空词库、日限额用完 | 正式模式不伪造新词/重复评分；可以明确仅练习、休息或退出，不改变战斗数值凑通关 |
| 同一任务在 Web/CLI/两个 run 同时处理 | 只有一次正式效果和一个贡献目标；冲突不会自动重放评分或授能 |
| Again 后求助、经典卡片做营地委托 | 真实失败入日志；引导不补 Good；同回合只授能一次，未绑定旧事件不能倒灌进度 |
| 满手、空堆、灼烧致死、奖励不足 | 规则有唯一结果；无无穷抽牌/多次敌方攻击/空奖励弹窗卡死 |
| 失败救援、应用退出、重开周目 | 暂停保持现场，救援结束节点；新 run 可正常构筑，账号纪念品/关系不重复刷 |
| 第二本书与第四位伙伴 | 从可编辑内容到校验/打包/安装/相遇/加入/技能/服装/回看全链成立，不改业务源码 |
| 同书增加章节、同系列新作 | 旧版 run 固定，升级只在安全检查点；继承指定结局白名单，不意外读另一周目的 flags |
| 移除包或缺角色资源 | 保留学习/回忆和可恢复依赖，清楚提示缺失；不破图、不换成其他角色、不自动清数据 |
| 备份恢复后迟到请求 | 旧 dataEpoch 不能执行；历史回执保留诊断，新现场不重新领奖/抽牌 |
| GM 初始化/降权/测试时钟 | 默认管理员可登录、无固定公开密码；权限立即生效；沙盒与普通数据严格隔离 |

这些是实现验收要求，不是文档修改已经通过的业务测试。文档修订保持一处权威定义；
尚未实现的新 API 必须标 planned，原始核对过程留在忽略目录。
