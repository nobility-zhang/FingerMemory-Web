# FingerMemory 产品说明

状态：M0 方案基线，2026-11-14。

本文定义新版 FingerMemory 的目标、核心流程、学习规则、阶段范围和验收入口。会影响实现但尚未由用户确认的事项统一列在“待确认假设”，不把方案建议写成既定需求。

## 目标与非目标

### 目标

- 继续使用 FingerMemory-Web 仓库和已有 Git 历史建设新版，不另起一个失去历史的产品仓库。
- 面向个人长期使用，优先做桌面浏览器中的键盘练习体验。
- 数据默认保存在当前浏览器本地，支持完整备份和恢复，不依赖旧 Java、Koa、MySQL、MongoDB 或 Redis 才能运行。
- 把词库、练习会话、作答记录、正式复习状态和交互模式分开，允许以后增加滚动、弹幕、卡片雨和提醒，而不复制掌握度。
- 使用经过验证的成熟 IndexedDB、TSV 解析和 FSRS 组件，不自行实现数据库、文本解析器或记忆算法。

### 非目标

- 本版不接入 AI，不把 AI 作为产品运行时能力。
- 第一阶段不做账号、云同步、多人协作、远程插件安装或插件市场。
- 不继续扩展旧 Java/Koa 双后端，也不要求服务器安装 Node。
- 不把旧数据库、旧页面的实现现状自动解释成新版业务规则。
- 不在 M0 设计 M4 之后模式的全部交互细节。

## 使用场景与主要流程

主要使用者是个人学习者，典型设备为桌面浏览器和物理键盘。

1. 用户创建一个或多个词库，录入词条，或从 TSV 文件预览并导入。
2. 用户选择词库、练习模式、新词量和复习量，开始一次练习会话。
3. 看词抄写、浏览答案等模式可以产生练习记录，但不自动改变正式复习状态。
4. 默写模式隐藏答案，用户主动回忆并输入；只有满足正式复习条件并由核心提交评分时才更新 FSRS 状态。
5. 用户可以中途离开，之后恢复未完成会话；恢复不能重复提交同一次作答或复习。
6. 用户定期导出完整备份；恢复必须先校验，失败时保持现有数据不变。
7. 后续可信模式通过统一插件接口读取会话事件并调用核心命令，不直接写另一套掌握度。

## 领域词汇

| 词汇 | 含义 |
| --- | --- |
| 词库 | 用户组织学习内容的集合，只负责成员关系和顺序。 |
| 词条 | 英文拼写、中文释义、可接受拼写和提示等静态内容，不直接携带掌握度。 |
| 学习目标 | 引用一个词条并声明练习方向的调度对象；首版只支持“中文释义 -> 英文拼写”。 |
| 练习会话 | 一次有开始、结束、暂停状态的学习活动，保存模式和队列快照。 |
| 练习记录 | 对展示、输入、提示、显示答案、放弃等行为的记录。 |
| 正式复习 | 满足主动回忆条件、由用户确认评分，并在一个事务中更新复习状态与日志的提交。 |
| 模式 | 提供刺激呈现和交互的模块；第一版只随项目构建，不允许远程加载。 |

## 学习规则

以下规则来自用户已明确的产品边界，是后续实现的硬约束。

1. 词库、会话、作答、复习状态和模式是不同领域对象，不能用 UI 组件的局部状态代替持久化事实。
2. 同一学习目标只有一份正式复习状态，由核心调度模块维护；不同模式只能发出练习事件或调用同一复习命令。
3. 看词抄写、浏览卡片、显示答案和动画展示可以记录练习，但不能自动算作成功回忆。
4. 输入速度、动画得分、卡片消失时间不能直接决定 FSRS 评分。
5. 一次正式复习提交必须带稳定提交标识；同一提交只能生效一次，复习状态和复习日志必须原子保存。
6. 新词量和复习量可配置，用户可以暂停增加练习，队列不能因为未完成积压而无限增长。
7. 插件不得直接写入 FSRS 状态；模式卸载时必须清理键盘、计时器、动画帧、观察器和事件订阅。
8. 词条本身与学习目标分离；同一词条将来可以派生不同学习方向，但每个学习目标只有一份正式复习状态。
9. 正式评分只能来自用户的明确选择。输入是否正确、是否手误、速度和动画表现只能作为作答事实或门禁条件，不能自动映射为 Again/Hard/Good/Easy。
10. 每个模式都通过同一个正式复习命令提交；动画模式默认写练习记录，必须满足与键盘模式相同的隐藏答案、无提示、无揭晓、用户确认评分条件才能更新 FSRS。

### 当前实现的正式复习门禁（A1 仍待确认）

当前核心按以下保守规则实现；其中提示后是否永远失去正式复习资格仍是待确认项：

- 正式复习只接受“答案尚未显示且未使用提示时完成的主动回忆”。
- 用户输入正确或错误只形成作答事实，不自动形成 FSRS 评分；评分必须由用户确认。
- 使用提示、显示答案或主动放弃后，本次作答默认为练习记录，不更新 FSRS。
- 输入错误后允许重试；是否允许同一次学习目标在一次会话中产生多次正式复习，必须由 A3 决定。
- 每次评分前展示 Again/Hard/Good/Easy 的含义和预计间隔；用户的最终选择才是评分输入。

## 阶段验收

### M1

- 用户能创建、重命名和删除空词库；删除非空词库必须明确确认。
- 用户能新增、编辑、删除词条，并为学习目标保存笔记。
- TSV 导入先展示有效行、无效行和重复项，再由用户确认提交；取消或解析失败不写入数据。
- 制表符原样参与分列，不因兼容旧 CLI 而静默替换为空格。
- 刷新页面后词库、词条和笔记一致；浏览器重启后的实际持久化由浏览器测试验证。
- 完整备份能在空数据库和新数据库恢复；非法、被截断或不支持版本的备份失败时，现有数据保持不变。

### M2

- 看词抄写明确标记为练习，不改变正式复习状态。
- 隐藏答案默写记录输入、提示、显示答案、放弃和重试等事件。
- 错词重练只改变当前会话队列，不创建第二套复习状态。
- 刷新、关闭标签页或应用重启后能恢复到兼容的会话位置；已完成作答不会重复写入。

### M3

- 到期队列、新词队列和会话上限可配置，暂停后不再取新内容。
- 同一学习目标在不同模式中得到同一份 FSRS 状态。
- 同一提交标识重复提交只返回第一次结果，不新增日志、不再次推进计划。
- 调度状态与复习日志在同一事务成功或失败；恢复备份后两者关系仍可校验。

### M4

- 歌词式滚动使用持久化会话队列；当前目标始终只有一条高亮行，输入框同时显示该目标的中文释义。
- 点击其他待练歌词行、切换键盘对照视图或在恢复后继续，都不会自动提交当前答案。
- 速度只控制歌词定位动画；暂停会冻结模式和输入并保留草稿，后台切换自动暂停。
- 减少动画模式跳过动画过渡，但仍保留相同的目标高亮和输入归属。
- 提示、显示答案和跳过分别记录为练习；动画结束、页面切换或超时都不会自动记对或记错。
- 退出模式会暂停并保存会话；再次进入可继续原队列。卸载时移除监听，不保留 interval、动画帧或音频。
- 键盘对照与歌词滚动共享同一会话、队列、学习目标和正式复习状态，只替换呈现方式。

## 待确认假设

以下事项会改变用户可观察行为或数据兼容，实施到对应门禁前需要确认。

| ID | 待确认问题 | 当前建议 | 影响阶段 |
| --- | --- | --- | --- |
| A1 | 使用提示、显示答案或主动放弃后，本次作答是否还可能进入正式复习？ | 一律只记练习，不更新 FSRS；需要正式复习时重新发起一次干净回忆。 | M2、M3 |
| A3 | 同一学习目标在一次会话中答错后重试成功，允许产生一次还是多次正式复习？ | 每个学习目标每次会话最多一次正式复习，以第一次正式提交为准。 | M2、M3 |
| A4 | 相同拼写但释义不同的词条是否共享学习目标？ | 默认以“规范化词面 + 主释义”识别学习目标；导入时展示合并候选，不静默合并。 | M1、M3 |
| A5 | 每日边界和复习队列按哪个时区计算？ | 以浏览器当前 IANA 时区的本地午夜为学习日边界，时间点本身以 UTC 毫秒保存。 | M3 |
| A6 | 插件第一版是否需要第三方代码和运行时权限隔离？ | 仅允许随项目构建、经代码审查的可信模块；提供生命周期和注册表，不声称具备沙箱。 | M5 |

## 成功标准

- 用户不需要保留旧后端进程即可完成导入、练习、复习、备份和恢复。
- 任何模式都不能在核心之外形成第二套正式掌握度。
- 关键失败路径有自动化验证：坏 TSV、坏备份、重复提交、事务中断、会话恢复和浏览器刷新。
- 文档、数据格式和实际行为保持一致；未运行或无法运行的检查明确记录为未验证。
