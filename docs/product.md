# FingerMemory 产品说明

更新：2026-11-16。当前目标为“中世纪异世界美少女伙伴陪伴的学习 JRPG”。本文与 `ui-direction.md`、`architecture.md`、`progress.md` 共同定义下一轮实施；G1 已交付莉娅、瑟琳、暖灯旅店入口、真实伙伴切换、陪伴密度和经典卡片入口。内容包、Three.js 探索和第一章闭环尚未实现。旧学园科幻方向和按四种输入呈现分割首页的 P4 计划被本次要求替代。Java 多用户、FSRS、数据迁移和 CLI 目标继续有效。

## 产品承诺与范围

用户希望打开应用时，感受到几位有性格、有立绘、有故事的美少女伙伴在等自己一起冒险；记忆单词是共同旅程中的行动。经典 Anki 式卡片始终是一等入口，可以跳过剧情和动画完成学习。

已确认要求：中世纪异世界背景、JRPG 氛围、多位关怀型伙伴、生成角色立绘、使用 Three.js 制作实际互动、一部词库对应一段可导入和更新的冒险。用户提供的气质参照是《兰斯》的希露与《公主连结》的可可萝；世界氛围参照《兰斯》《Re:从零开始的异世界生活》《无职转生》《为美好的世界献上祝福》。采用温柔照顾、旅途陪伴、魔法与日常喜剧这些创作方向；新角色、地名、剧情、美术为原创，不把参考作品的情节当作本项目设定。

首轮完成可游玩的短篇闭环：两位伙伴、一个词库冒险包、一章包含探索与回合制遭遇的故事、可独立使用的翻面卡片。完整首部内容扩为三章与第三位伙伴。角色名、世界名和美术配色为本规划默认创作方案，可在首段体验评审后修改。

运行时不接入 AI。立绘与背景可在制作阶段用图像生成工具制作；剧情、对白、规则和素材均打包后确定性运行。无开放世界、实时动作战斗、抽卡、体力收费、公开排名或远程代码插件的首版需求。

## 世界与故事

工作标题为《星灯旅团》，世界称为“弥尔兰”。失语之雾让道路铭文、古老契约和村民的书信逐渐模糊。玩家拥有“记文者”的能力，与伙伴恢复文字、连接村落并找回各自珍惜的记忆。语言学习可以表现为辨认路标、修复咒文、整理药剂说明和解读信件；不能为剧情编造错误词义，技术英语和考试词库也沿用原释义。

气氛是温暖旅店、森林遗迹、石桥、修道院、冒险公会、魔法与有分寸的日常喜剧。戏剧冲突来自旅途、误解和共同解决困难，伙伴不会因玩家忘词或几天没来而责备、冷落或扣好感。

| 章节 | 故事与伙伴 | 玩家行动 | 学习结合与结尾 |
| --- | --- | --- | --- |

| 第三章 黎明前的修道院 | 三位伙伴各自补全一段记忆，决定修复古钟而非破坏它 | 组合已学会的探索技能，通过护送与最终封印回合 | 结束后获得旅团纪念 CG 和完整信件；未掌握的词继续按 FSRS 安排，不因通关变为熟练 |

### 第一章可直接制作的节点与对白

以下是样例包的起始脚本，作者可润色文字但保留可观察的分支与检查点。剧情界面不要提前显示尚待考核的英文词面。

| 稳定节点 ID | 内容与默认对白 | 选择与保存 |
| --- | --- | --- |
| `inn.arrival` | 莉娅把灯放在桌边：“信上的字又淡了一些。不过，寄信的人一定还在等回音。”瑟琳：“古钟修道院的印记还在。也许我们能沿着它找到路。” | 开始委托 / 先做营地复习；两条路径都能返回旅店 |
| `inn.preparation` | 莉娅：“我带了药草和热茶。你想先看地图，还是先读一小段信？” | 选择只改变伙伴短对白与 flags，不赠送记忆正确率或解锁答案；保存出发检查点 |
| `forest.signpost` | 点击倾斜路标与旧灯座。瑟琳：“先看清楚，再往前走。这次不用赶时间。” | 调查路标 / 查看灯座 / 扎营；调查两者合流到溪桥，不把必需学习内容藏在错过就消失的分支 |
| `bridge.guardian` | 莉娅：“桥在雾里。等你准备好了，我会把灯举起来。”进入明确的学习与行动界面 | 三个小回合后选择护盾、破雾或协助；显示消耗和预期效果；可随时撤退 |
| `bridge.crossed` | 瑟琳：“路标重新亮起来了。你刚才记下的东西，真的让这条路有了方向。” | 成功解除迷雾，设置 `bridgeResolved=true`；一次性记念事件 |
| `bridge.assisted` | 莉娅：“先抓住我的手。没关系，我们可以借着这盏灯慢慢走过去。” | 策略失败或请求救援也能过桥，保存 `bridgeAssisted=true`；不伪造新复习、不扣伙伴关系 |
| `camp.letter` | 第一段信恢复：“如果钟声还在，请告诉回家的旅人，灯一直亮着。”莉娅：“原来，等着回信的人不止我们。” | 休息 / 回看今日笔记 / 继续已安装章节；保存检查点 |
| `chapter1.end` | 镜头看向森林后的钟楼，瑟琳把信夹进旅记：“明天想从这里继续的话，我会替你留好这一页。” | 第一章结算与退出；后续未安装章节明确标记，不能跳空页面 |

样例词条可采用 lantern（提灯）、bridge（桥）、promise（承诺）及若干生活/旅行词；词义来自包内词库，剧情只提供情境。正式问答以前不把中英答案并排放在路标上；揭晓后的符文光效可展示已回答的词。

### 对白事件与节奏

对白由内容包中的固定文本与白名单变量组成，基于学习/故事事件选择；同事件从有限候选轮换，避免逐字实时生成。只在开场、显式评分后、休息、遭遇结果和章节节点出现，不在打字中抢焦点或覆盖答案。

- 欢迎：莉娅“热茶刚好。今天想先整理旅途笔记，还是去看看桥边的路标？”
- Again：瑟琳“这一枚符文还不熟悉。我们记下它，之后再一起遇见。”
- 完成小组：莉娅“这些已经收好了。接下来的路，我陪你慢慢走。”
- 主动休息：菲妮“地图不会跑掉。先在这里扎营吧，我来盯着篝火。”
- 离开多日后：莉娅“欢迎回来。上次的书签还在，你想从那里继续吗？”

提供安静、标准、丰富三档；标准档每小组优先至多一条主动陪伴短句，用户主动点伙伴不计此限。触发频率、重复抑制与台词版本是可配置数据。亲密度来自去重的共同经历与章节事件，和 Again/Hard/Good/Easy 等级无关；不按连续签到惩罚，不做刷重复点击的奖励。

## 核心玩法

首页主入口为“继续冒险”“营地复习”“我的旅记”，另有伙伴、书架和设置。歌词滚动、弹幕、卡片雨不再是产品必须保留的四个并列模式；旧数据和可用入口在迁移期保留为“经典练习”，其呈现能力可以复用于咒文、飞行符文或场景特效。

### 一轮冒险的可观察闭环

1. 在旅店选词库冒险与带队伙伴，查看本轮学习量和可恢复进度。
2. 在 2.5D 场景选择路标、物件或道路；探索产生对白、分支或遭遇，而不写 FSRS。
3. 进入遭遇后暂停场景操作，出现 DOM 卡片或拼写回忆区域；一次只回答一个清晰目标。
4. 显式完成一个学习回合后得到一次基础行动能量；各档有效记忆评分能量相同。
5. 玩家选择破雾、护盾或伙伴协助，场景中的屏障、队伍或敌人状态真实改变；技能克制和行动选择决定不同反馈。
6. 达成本遭遇既定回合目标后触发故事节点、伙伴对白和一次性纪念品，保存后可以退出。

首个遭遇是溪桥迷雾守卫：读懂三枚路标并为队伍积累行动能量，选择护盾减轻迷雾扰动，或破雾解除路障，瑟琳/莉娅协助表现不同。战斗数据不写入学习掌握度。没有限时抢答和“必须全对才给剧情”；Again 是真实的学习结果，仍能推动本次尝试。跳过无作答不发能量，可走撤退/伙伴救援的叙事路径继续，但不伪造已学习状态。

奖励、节点解锁和遭遇回合只消费去重且被核心确认的学习事件。成功响应丢失时显示待确认，不让动画宣告已经获得奖励。点击、播放动画和读取旧日志都不能再次记账。

### 溪桥遭遇的首版规则

默认三项可用学习目标，每项合法完成提供 1 能量，初始迷雾 2、屏障 2，能量上限 3。界面明确显示规则和动作预览：破雾消耗 1 能量，屏障减 1、迷雾加 1；护盾消耗 1 能量，迷雾减 2（最低 0）；伙伴协助消耗 2 能量，屏障减 1、迷雾减 1（最低 0）。每次动作先判断迷雾是否达到 4，达到则进入救援；否则屏障归零则成功；能量用尽且未成功也进入救援。这样“护盾→破雾→破雾”和“伙伴协助→破雾”可通关，盲目连续破雾会进入不同剧情分支。所有变化来自策略选择，与自评 Again 或 Easy 无关。

这是内容配置示例，不应写成全局硬编码。实际可用目标不足三项时先让玩家选择营地练习或推迟遭遇；教学回合若启用，由包声明采用一次性 guided-practice 事件，不能突破正式复习上限或假造新词。成功与救援都只结算同一章节一次性奖励的一个分支，重读不额外领取。

### 经典卡片与学习规则 v2

保留独立的 Anki 式“问题 → 心中回忆 → 翻面 → 自评”入口，以及键盘拼写入口。与冒险使用同一个学习目标和调度状态；同一目标不能因为换场景或伙伴创建新掌握度。

现有代码的 A1 把所有揭晓行为都排除出正式评分，不能直接承担翻面卡片。本轮明确设计 `assessmentPolicyVersion=2` 和三个不同流程，实施时必须修改前后端门禁、会话、API、日志校验与测试，不能只加一个翻面按钮。

| 流程 | 提交规则 | FSRS |
| --- | --- | --- |
| `flashcard-self-report` | 先呈现问题，玩家尝试回忆；翻面是检查结果，随后显式选 Again/Hard/Good/Easy | 翻面之后可以正式评分；“没想起”应能直接进入揭晓并选 Again，不能被迫编造一个错误答案 |
| `typed-recall` | 隐藏答案输入，提交后对照并显式评分；单词输入过程不泄露逐字正误 | 独立回忆记录有效；回答失败选择“没想起”可记录 Again；请求救助后不能再把抄对记成 Good/Easy |
| `guided-practice` | 看词、提示、跟读、抄写、预览或剧情中已展示答案后的练习 | 只记练习，不更新正式掌握度 |

自评无法证明玩家脑中的回忆过程，界面准确说明自评含义，服务端验证合法状态转换、显式评分和幂等，不声称能防止所有自评失真。提示前的失败通过明确 Again 事件留下；不能让遗忘总是只落入练习而导致调度长期高估记忆。

保留 A3 的同一学习目标同一会话至多一次正式提交；算法安排的下次学习步骤通过到期队列/下一会话发起。重复尝试只记练习。旧日志标为 `legacy-v1`，不回算、不补发遗忘或奖励，FSRS 引擎和参数版本不因此更换。

进入遭遇前按当前队列计划冻结目标与能力，区别阅读曝光与考核。剧情不能在正式提问前显示目标英文、答案译文组合或自动播放答案；若故事必须展示答案，该目标本回合进入 guided-practice。卡片使用 `assessmentType`；场景使用 `encounterType`；二者不合并为一个“游戏模式”枚举。

### 学习队列与剧情进度

- 待复习优先，保留新词量/复习量上限和暂停；不为看完一章强行添加几十个新词。
- 跨词库的到期项目可在营地处理，故事章节的新词来自该章节的显式绑定。
- 熟悉内容可以由当前状态判断跳过教学，具体章节资格记录在进度中，不靠词面推测共享。
- 章节能暂停在小检查点；当天没有待复习且不想学新词时可以看已解锁剧情、互动或退出。
- 经典卡片完成的有效事件可计入已激活的当前章节委托；同一事件不能在多本冒险重复领取同一种奖励，也不能回放旧日志刷关。

## 词库冒险包与扩展

一本词库对应一部有开端、推进和结局的冒险；词条数据与叙事资源分离但一起导入。定义 `.fmbook` 版本化 ZIP 包，最小包含清单、词条、章节/节点、对白、词条绑定、资源清单。契约、事务与包安全见 `architecture.md`。

- 成品故事包拥有作者编写的独立剧情与场景，玩家导入即能开始。
- 普通 TSV 仍能导入：可以只作为词库，也可显式选择“旅团委托”模板，按条目数量形成章节任务。此路径是固定模板实例化，不宣称为每本书自动创作全新故事。
- 内容作者可以制作新书包和章节更新，不修改应用代码；只能组合已注册节点/遭遇类型，不携带脚本。
- 包更新先预览变化，进行中的冒险固定在原版本，升级使用明确的节点/词条映射；不重置学习状态或重复发奖。
- 通关后提供重读与再探索，重复阅读不等于重复正式复习。
- 分享的内容包只包含内容和素材，不含私人笔记、账号凭据、个人 FSRS 状态或存档。

## 多用户与 CLI

现有 Java + MySQL + 固定 TS-FSRS worker 继续作为账号模式边界，本地模式继续可独立使用。所有故事进度、伙伴偏好、亲密度、奖励和检查点都属于用户，和账号缓存、幂等、版本检查一起隔离。

CLI 继续在原仓库迭代，提供登录、词库、卡片/拼写、复习、备份和 `adventure list/start/resume` 等文字冒险入口。以同一内容图展示对白和选择，复用服务端进度，不要求终端渲染 Three.js 或立绘。节点都有文本降级说明；Web/CLI 交接从已提交检查点恢复，不传画面帧或动画时间。CLI 的卡片翻面与评分必须遵循学习规则 v2。

## 成功标准
